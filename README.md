# CPU Attention Suite

Cache-oblivious self-attention algorithms on CPU (C++17, OpenCilk, Eigen).

## Building

Builds require the OpenCilk compiler; locally use the `opencilk:v3.0` docker image:

```bash
docker run --rm -v "$PWD":/work -w /work opencilk:v3.0 ./build_solvers_release.sh
```

This produces `build/attention_solver`. Set `MARCH=...` to override `-march=native`.
`./debug_build.sh` builds `build/attention_solver_debug`; with `CILKSAN=1` it is instrumented
with the Cilksan race detector.

## Running

```bash
CILK_NWORKERS=16 build/attention_solver fa2 --random 65536 -b 64 -w 1 -r 5 --json
python python_scripts/generate_problem.py -N 65536 -d 64 -o data/problem_65536_64.npy --seed 424
CILK_NWORKERS=16 build/attention_solver fa2 data/problem_65536_64.npy -b 64 -w 1 -r 5 --json
```

Algorithms: `reference`, `standard`, `streamed`, `fa2`, `recursive`, `summary` (alias `rec`;
requires `-p` to be a power of 4, defaulting to `CILK_NWORKERS`), `query`, `hybrid` (any `p`).
Backward algorithms: `standard_bwd`, `fa2_bwd`. They also need the upstream gradient dO, from a
(4, N, 64) [Q, K, V, dO] problem file or `--random`; an untimed FA2 forward pass supplies O and the
log-sum-exp L, and `-o` writes the stacked (3, N, 64) [dQ, dK, dV].
Run `build/attention_solver` with no arguments for the full option list.

## Testing

```bash
python python_scripts/run_tests.py --docker opencilk:v3.0   # or omit --docker on Linux
```

Validates the C++ `reference` solver against a float64 NumPy reference, then checks every
solver configuration (block sizes, `p`, worker counts) against the C++ reference. Backward
solvers are checked per gradient (dQ, dK, dV) against a float64 NumPy backward pass. Use
`--quick` for a reduced set, `-k <algorithm>` to filter, and `-v` to print passing checks.

## Benchmarking

`python_scripts/benchmark.py` runs the full experiment set on one machine: it builds the solver
for that machine, tunes each solver's parameters at a demo size, then sweeps N (2^12 to 2^22 by
default) with `--reps` (default 10) repetitions per experiment. Inputs are generated by the
solver itself (`--random N`), so only the Python standard library is needed.

```bash
python3 python_scripts/benchmark.py --results-dir /path/outside/repo --label mymachine
```

Results go to `<results-dir>/<label>/` as one JSON file per experiment (`tune/`, `sweep/`,
`papi/`), plus `tune/best.json` and per-run machine info in `runs/`. Each file is updated after
every repetition, so an interrupted run resumes where it stopped when rerun with the same
command (exit code 3 means "stopped early, rerun to continue"). Useful options: `--threads`
(default: all physical cores), `--max-n`, `--algorithms`, `--phases`, `--time-limit`,
`--max-rep-seconds`; see `--help`.

In the docker image:

```bash
docker run --rm -v "$PWD":/work -v /path/to/results:/results -w /work opencilk:v3.0 \
  python3 python_scripts/benchmark.py --results-dir /results --label docker
```

### Cache misses (PAPI)

With `--papi` the driver also builds `attention_solver_papi` (`PAPI=1 ./build_solvers_release.sh`,
using `PAPI_INC`/`PAPI_LIB` or TACC's `TACC_PAPI_INC`/`TACC_PAPI_LIB`) and repeats the N sweep
recording L1/L2/L3 misses (`--papi-events`), summed over all worker threads, for the solve only.
This needs a Linux machine with hardware counters available to user processes
(`kernel.perf_event_paranoid` <= 2); it does not work inside docker on macOS.

### TACC Stampede3

`slurm_jobs/{skx,icx,spr}.slurm` run everything (including PAPI) on one node of each type with a
2 hour limit, stopping cleanly 10 minutes before it. Submit from the repository root, adding
`RESUBMIT=1` to keep resubmitting until all experiments finish:

```bash
sbatch --export=ALL,RESUBMIT=1 slurm_jobs/skx.slurm
```

Results go to `$SCRATCH/cpu_attention_results/<label>`. Settings such as `REPS`, `MAX_N`,
`MODULES` and `RESULTS_DIR` are documented at the top of `slurm_jobs/run_benchmark.sh`.

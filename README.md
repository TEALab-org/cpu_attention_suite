# CPU Attention Suite

Cache-oblivious self-attention algorithms on CPU (C++17, OpenCilk, Eigen).

## Building

Builds require the OpenCilk compiler; locally use the `opencilk:v3.0` docker image:

```bash
docker run --rm -v "$PWD":/work -w /work opencilk:v3.0 ./build_solvers_release.sh
```

This produces `build/attention_solver`. Set `MARCH=...` to override `-march=native`.
`./debug_build.sh` builds `build/attention_solver_debug`; with `CILKSAN=1` it is instrumented
with the Cilksan race detector.

## Running

```bash
CILK_NWORKERS=16 build/attention_solver fa2 --random 65536 -b 64 -w 1 -r 5 --json
python python_scripts/generate_problem.py -N 65536 -d 64 -o data/problem_65536_64.npy --seed 424
CILK_NWORKERS=16 build/attention_solver fa2 data/problem_65536_64.npy -b 64 -w 1 -r 5 --json
```

Algorithms: `reference`, `standard`, `streamed`, `fa2`, `recursive`, `summary` (alias `rec`;
requires `-p` to be a power of 4, defaulting to `CILK_NWORKERS`), `query`, `hybrid` (any `p`).
Backward algorithms: `standard_bwd`, `fa2_lockfree_bwd` (two sweeps, no locks), `fa2_locking_bwd`
(one sweep, locked dQ updates), `summary_bwd` (ParallelDenseBackward; power-of-4
`-p`), `owned_bwd` (ParallelOwnedBackward; `-g`), `hybrid_bwd` (any `p`). They also need the upstream gradient dO, from a
(4, N, 64) [Q, K, V, dO] problem file or `--random`; an untimed FA2 forward pass supplies O and the
log-sum-exp L, and `-o` writes the stacked (3, N, 64) [dQ, dK, dV].
Run `build/attention_solver` with no arguments for the full option list.

### Sparse attention

`sparse_fwd` is the query-owned mixed sparse forward (Algorithm 19 of the exposition). It combines
a structural mask with exactly zero query rows and jointly zero key/value rows. `sparse_bwd` is the
matching backward with query and key/value ownership (Algorithms 32-34), which also skips zero
upstream-gradient rows; its untimed setup runs `sparse_fwd` on the same inputs for O and L. The mask is built
as a quadtree during setup (untimed) from a pattern or a dense file:

```bash
CILK_NWORKERS=16 build/attention_solver sparse_fwd --random 262144 -b 64 -g 256 \
  --mask block --mask-density 0.25 --mask-tile 256 --zero-q 0.3 --zero-run 256 -w 1 -r 5 --json
```

- `--mask none|block|band|element` with `--mask-density` (fraction of allowed pairs) and
  `--mask-tile` (block pattern), or `--mask-file` for a dense `(n, n)` uint8 mask at small n.
  The diagonal is always allowed, so every row is nonempty.
- `--zero-q`, `--zero-kv`, `--zero-do`: fractions of rows set exactly to zero, placed in aligned runs
  of `--zero-run` rows (1 disperses them). These apply to any solver, so dense solvers can run on the
  same inputs.
- `--shortcuts`: which zero-row shortcuts the sparse solver uses (`q,kv,do`, a subset, or `none`).
- `--dump-mask F` writes the built mask as a dense `.npy` and exits (small n).

## Testing

```bash
python python_scripts/run_tests.py --docker opencilk:v3.0   # or omit --docker on Linux
```

Validates the C++ `reference` solver against a float64 NumPy reference, then checks every
solver configuration (block sizes, `p`, worker counts) against the C++ reference. Backward
solvers are checked per gradient (dQ, dK, dV) against a float64 NumPy backward pass. Use
`--quick` for a reduced set, `-k <algorithm>` to filter, and `-v` to print passing checks.

## Benchmarking

`python_scripts/benchmark.py` runs the full experiment set on one machine: it builds the solver
for that machine, tunes each solver's parameters at a demo size, then sweeps N (2^12 to 2^22 by
default) with `--reps` (default 10) repetitions per experiment. Inputs are generated by the
solver itself (`--random N`), so only the Python standard library is needed.

```bash
python3 python_scripts/benchmark.py --results-dir /path/outside/repo --label mymachine
```

Results go to `<results-dir>/<label>/` as one JSON file per experiment (`tune/`, `sweep/`,
`papi/`), plus `tune/best.json` and per-run machine info in `runs/`. `--pass backward` benchmarks
the backward solvers instead, into `tune_backward/`, `sweep_backward/` and `papi_backward/`. Each file is updated after
every repetition, so an interrupted run resumes where it stopped when rerun with the same
command (exit code 3 means "stopped early, rerun to continue"). Useful options: `--threads`
(default: all physical cores), `--max-n`, `--algorithms`, `--phases`, `--time-limit`,
`--max-rep-seconds`; see `--help`.

In the docker image:

```bash
docker run --rm -v "$PWD":/work -v /path/to/results:/results -w /work opencilk:v3.0 \
  python3 python_scripts/benchmark.py --results-dir /results --label docker
```

### Cache misses (PAPI)

With `--papi` the driver also builds `attention_solver_papi` (`PAPI=1 ./build_solvers_release.sh`,
using `PAPI_INC`/`PAPI_LIB` or TACC's `TACC_PAPI_INC`/`TACC_PAPI_LIB`) and repeats the N sweep
recording L1/L2/L3 misses (`--papi-events`), summed over all worker threads, for the solve only.
This needs a Linux machine with hardware counters available to user processes
(`kernel.perf_event_paranoid` <= 2); it does not work inside docker on macOS.

### Sparsity

`--phases sparsity` (not in the defaults) times the pass's sparse solver (`sparse_fwd`, or
`sparse_bwd` with `--pass backward`) at one N (`--sparsity-n`, default 2^18), varying one kind of
sparsity at a time over `--sparsity-levels` (default 0, 0.25, 0.5, 0.75, 0.9, 0.95, 0.99): a
block-random mask (`--mask-tile`, default 256), a banded mask, zero Q rows, jointly zero K/V rows
and, for backward, zero dO rows (`--sparsity-types`; `element` adds the element-random stress
test). The level is the fraction of query-key pairs masked out or of rows zeroed; level 0 runs
once and is shared by every kind. The sparse solver is tuned at `--tune-n` with nothing sparse,
like the dense solvers. Results go to `sparsity/` (`sparsity_backward/`), and each record keeps
the achieved mask density and zero-row counts. The dense baselines are the dense sweep at the
same N, so run the dense benchmarks on the same machine label.

```bash
python3 python_scripts/benchmark.py --results-dir /path/outside/repo --label mymachine \
  --algorithms sparse_fwd --phases build,tune,sparsity
```

### TACC Stampede3

`slurm_jobs/{skx,icx,spr}.slurm` run everything (including PAPI) on one node of each type with a
2 hour limit, stopping cleanly 10 minutes before it. Submit from the repository root, adding
`RESUBMIT=1` to keep resubmitting until all experiments finish:

```bash
sbatch --export=ALL,RESUBMIT=1 slurm_jobs/skx.slurm
sbatch --export=ALL,PASS=backward,RESUBMIT=1 slurm_jobs/skx.slurm
sbatch --export=ALL,SPARSITY=1,RESUBMIT=1 slurm_jobs/skx.slurm
sbatch --export=ALL,SPARSITY=1,PASS=backward,RESUBMIT=1 slurm_jobs/skx.slurm
```

Results go to `$SCRATCH/cpu_attention_results/<label>`. Settings such as `REPS`, `MAX_N`,
`MODULES` and `RESULTS_DIR` are documented at the top of `slurm_jobs/run_benchmark.sh`.

### Figures and tables

```bash
python python_scripts/plot_results.py --results-dir <results-dir> --output-dir <out> [--normalize] [--pass backward]
python python_scripts/make_table.py --results-dir <results-dir> --output-dir <out> [--n 1048576] [--pass backward]
python python_scripts/make_tuning_table.py --results-dir <results-dir> --output-dir <out> [--pass backward] [--fragment]
python python_scripts/plot_sparsity.py --results-dir <results-dir> --output-dir <out> [--pass backward] [--baseline self]
python python_scripts/plot_sparsity_runtime.py --results-dir <results-dir> --output-dir <out> [--pass backward]
```

`plot_results.py` draws runtime and L1/L2/L3 misses over N with one column per architecture;
`--normalize` divides by N^2. `make_table.py` writes a LaTeX (booktabs, multirow) table at one N; `--memory` adds each
algorithm's peak memory above its inputs (GiB) from the timing sweep.
`make_tuning_table.py` writes a single-column table of the tuned b, g and p; `--fragment` leaves out
the table environment so the forward and backward tables can sit side by side in minipages.
`plot_sparsity.py` draws one panel per architecture with one series per kind of sparsity: speedup
over the fastest dense solver at the same N (or, with `--baseline self`, over the sparse solver with
nothing sparse) against the achieved work reduction, with the ideal speedup as a dashed diagonal.
`plot_sparsity_runtime.py` draws the same panels with runtime on the y axis instead, plus the ideal
(the nothing-sparse time scaled by 1 - s, dashed) and the fastest dense solver's time (dotted).
